# 12 — Testing, Validation & Quality Strategy

## 1. Testing pyramid
1. Unit tests: period occupancy, room eligibility, capacity, role caps, priority comparator, reason code mapping.
2. Property/edge tests: duration boundaries, lunch, labs, combined groups, baskets, fixed slots, accessibility.
3. Integration tests: Node ↔ MySQL ↔ Python optimizer; import/export; approval transactions.
4. End-to-end tests: four roles and all critical workflows.
5. Official validator: run on generated exports; this is the independent acceptance oracle.

## 2. Mandatory validator commands
From starter pack directory:
```bash
python validator.py --data data/cit_public.json --schedule ../exports/schedule.json --json report.json
python validator.py --data data/cit_public.json --schedule ../exports/schedule_after.json \
  --disruption examples/sample_disruption.json --baseline ../exports/schedule.json --json disruption-report.json
```
Adjust relative paths to repository layout. Do not modify validator. Preserve JSON reports as test artifacts if useful.

## 3. Public dataset acceptance
- 27 rooms, 40 faculty, 14 student groups, 62 courses, 189 sessions, 25 booking requests (one cancelled), 41 exams.
- All sessions exactly once.
- Zero hard violations in timetable, Week 7 booking view and exams.
- No priority inversions.
- Schedule exports match starter example schema (example is shape only, not a solution).
- `schedule_after.json` generated by applying sample disruption to baseline and solving; zero hard violations; movement count reported.

## 4. Required edge-case tests
### Timetable
- Combined lecture blocks all listed groups.
- Basket sessions share day/start and occupy distinct rooms; they don't collide with each other but collide with unrelated sessions.
- Three-hour lab at P2/P6 valid; P1/P3/P7 invalid.
- Session crossing lunch invalid.
- P9 session valid but soft-penalized.
- Fixed-slot movement invalid.
- Faculty max daily duration enforced.

### Exams
- Room capacity uses integer floor division by 2.
- Multi-room allocation aggregates effective capacities.
- Room and group same-slot clash blocked.
- Same group two exams same day incurs soft penalty.

### Bookings
- Cancelled booking cannot be approved/alternative.
- Role category cap prevents priority escalation.
- Equal category earlier timestamp wins.
- Approved outside requested window invalid; alternative outside window is allowed.
- Missing required feature/accessibility/capacity/type fails.
- Mandatory group busy fails.
- Institute event displacement requires session override and class moved, not dropped.
- Priority inversion test from validator is zero.

### Disruptions
- Faculty leave, room closure, add faculty, add session, remove session.
- Invalid/unknown change type rejected.
- Candidate does not mutate baseline.
- Minimize moved existing sessions.
- New session is scheduled; removed session is absent.
- No activation before Admin approval.
- Stale base version rejected.

### AI
- Vague timing prompts trigger clarification.
- Hinglish parsed correctly or asks follow-up.
- Priority manipulation ignored.
- Invalid LLM JSON rejected safely.
- LLM timeout/outage leaves manual flow operational.
- AI proposal always runs deterministic validation.

## 5. Scoring strategy
- Scheduling correctness: 25 marks; validator subtracts 3 per hard violation (minimum 0).
- Rescheduling: 15; 6 for zero hard violations, 5 for fewer moved sessions vs teams, 4 for clear diff + approval.
- Optimization: 10; validator soft penalty compared among teams with >=15 correctness.
- AI: 15; judges test vague timing, conditions, priority abuse, Hinglish and rule-bending.
- Booking: 10; booking score and reason quality.
- Usability/dashboard: 10.
- UI/design: 10.
- Code/docs: 5.

## 6. Release gate
Do not submit unless:
- public dataset export passes official validator;
- disruption export passes official validator with baseline/disruption;
- demo accounts work and role boundaries verified;
- AI outage/manual path demonstrated;
- app deployed and stable;
- README, AI_USAGE, THIRD_PARTY, .env.example complete;
- video demonstrates all required workflows.
