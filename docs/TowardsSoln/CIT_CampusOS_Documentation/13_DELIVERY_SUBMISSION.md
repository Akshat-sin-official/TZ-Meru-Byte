# 13 — Delivery, Deployment & Hackathon Submission

## 1. Repository requirements (official)
Public GitHub repository created after hackathon starts. Must remain public and accessible. Preserve real commit history. Do not push commits or change deployed app after submission deadline if organisers prohibit it.

Required files:
- `README.md`: description, architecture diagram, tech stack, setup steps, demo accounts, known limitations.
- `.env.example`: every environment variable, no real secrets.
- `AI_USAGE.md`: all AI product/build usage and boundaries.
- `THIRD_PARTY.md`: OR-Tools and every third-party library/service with purpose/license where known.
- `exports/schedule.json`: generated by app for public dataset.
- `exports/schedule_after.json`: generated by app after sample disruption.

## 2. Deployment requirements
- Live deployed link must stay up until results announced.
- Four working demo accounts (one per role) must be listed in README.
- Admin demo account must have a reset-demo-data button.
- Ensure database persists across restarts; seed demo state on reset.
- Health checks for frontend/API/optimizer/DB.
- Do not depend on a developer laptop or local tunnel for judging.

## 4. THIRD_PARTY.md must include
- OR-Tools CP-SAT and version.
- Node dependencies and Python packages.
- LLM provider/model and API usage.
- Database/hosting provider if relevant.
- UI component and utility libraries.
- Licenses where available.

## 5. AI_USAGE.md must include
- Every model/API product calls and use case.
- AI coding tools used during development and which code/docs they helped create.
- Where prompts are stored.
- Explicit statement that AI does not decide validity, priorities, approvals or database writes.

## 6. Five-minute video plan
1. Login as Admin; show dashboard and dataset import/reset.
2. Generate timetable and show solver result + zero official validator violations.
3. Show group/faculty/room timetable views.
4. Enter English/Hinglish booking; show editable extraction and confirmation.
5. Demonstrate conflict blocked with clear reason.
6. Show Spectra decisions: approve/reject/alternative and priority reasoning.
7. Apply sample disruption; show old→new diff, moved count, pending Admin approval, then approve.
8. Show notifications and dashboard summary.
9. Briefly show AI outage fallback/manual form if time.

## 7. Deployment hardening checklist
- Run migrations on deploy; seed only safe demo data.
- Set CORS and secure cookies correctly.
- Store keys in host secret manager/environment.
- Set request body/file limits.
- Keep solver timeout and concurrency bounded.
- Persist generated artifacts and DB data.
- Ensure `/health` and `/ready` checks.
- Log exceptions without secrets.
- Test Admin reset on deployed environment before final video.
